# Last-wins: newest session, newest objective — v0.38.12 (2026-09-04)

The user's rule, verbatim in spirit: *if we make a new objective, the old
one dies or becomes irrelevant — the new one is the real objective and the
old is gone.* Two mechanisms, one philosophy.

## 1. Newest session wins the state root (no ceremony, no killing)

The v0.38.11 `/glla takeover` (confirm → SIGTERM → verify) stays for
explicit termination, but the common case no longer needs it: when a fresh
**main-host** `session_start` finds a live foreign owner, it steals the
claim (`supersedeLiveOwnerRoot`: unlink + fresh claim) and ledgers
`owner_superseded {prevPid, prevAt, prevSession, byPid, bySession}` with a
loud notice. The old process is never signaled — it notices on its next
throttled (30s) ownership recheck and stands down to read-only itself
(`owner_stood_down`, notified once per holder, silent recovery when the
holder dies and the heartbeat reclaims).

Safety, unchanged in spirit:

- Workers/subagents can never steal (`isMainHost: false` → refused). A
  subagent dethroning its own main session would be self-sabotage.
- Command entry rechecks standing (throttled, main sessions only), so a
  superseded session's commands refuse within ~30s instead of writing
  competitively. Subagents keep their own refusal wording.
- `stateRootPending` still refuses everything blind.

## 2. Newest objective wins the goal slot (never blocked)

- `/goal start <objective>` is explicit consent: the update/replace/cancel
  conflict dialog is skipped (choice ledgered as `replace
  via: start-explicit`). The plain `/goal <objective>` verb keeps the full
  dialog — inferred/ambiguous intent still asks.
- `setGoal` no longer refuses the new objective when the old one cannot
  archive. The honest archive is still attempted first; on failure the old
  objective — id, text, contract, status, scheduled resume, pending
  completion — is preserved inline in `goal_superseded_unarchived` and the
  new goal starts anyway ("starts anyway", never "not started").
