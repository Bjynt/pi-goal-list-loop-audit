## Completion summary

Fixed the issue where:
1. When switching models, /goal could be resumed but loops required a new /loop start
2. Loops did not survive (were resume-able but did not auto-continue) long context compaction (+10 minutes)

The root cause was that manual model selection during main-model recovery cancelled the recovery but did NOT reactivate the paused goal or stopped loop. Also, context overflow recovery (during compaction) did not reactivate the loop/goal after successful fallback model selection.

Changes made:
1. **extensions/loops/goal-activation.ts**: 
   - In the `model_select` handler: when user manually switches models during recovery, now properly reactivates the paused goal or stopped loop
   - In context overflow recovery: added call to `mainModelRecoverySucceeded(ctx)` after successful fallback model selection to immediately reactivate the loop/goal

2. **extensions/loops/goal-orchestrator.ts**:
   - Fixed `handleMainModelAgentEnd` to correctly differentiate between goals and loops for recovery entry:
     - Goals: enter recovery on ANY recoverable failure if active
     - Loops: only enter recovery if active AND has fallback chain configured

3. **extensions/goal-state.ts**: Added `__testOnlyResetMainModelRecovery()` test helper

4. Added comprehensive tests in `tests/model-switch.test.ts` verifying both goal and loop reactivation on manual model switch during recovery.
