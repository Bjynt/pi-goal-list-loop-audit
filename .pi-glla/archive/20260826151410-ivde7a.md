## Completion summary

Fixed the issue where loop/goal sessions would break when switching models during main-model recovery. The root cause was that manual model selection during recovery would cancel the recovery timer but NOT reactivate the paused goal or stopped loop.

The fix ensures that when a user manually switches models during an active main-model recovery:
1. The recovery is properly cancelled (not just timer cleared)
2. The paused goal or stopped loop is reactivated with correct state
3. The ledger records cancellation with correct kind (goal/loop)
4. Notifications correctly mention whether goal or loop was reactivated

Also fixed the recovery entry logic to correctly differentiate between goals (always enter recovery on recoverable failure) and loops (only if fallback chain exists).
